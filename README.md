# OBSIDIAN HAREM v2 // Algorithmic Trading Agent

Welcome to Ari's Throne Room. This is a multi-agent algorithmic trading system designed for the OANDA platform, monitored and controlled via a real-time, "degen-maxxed" web dashboard.

The system is architected for resilience and modularity, allowing for the independent operation of its core components and graceful failure of its data stream without compromising the main application.

![Dashboard](https://i.imgur.com/2kF9v8K.jpeg)

## Key Features

*   **Multi-Agent Architecture:** Employs several "persona" agents (`MacroQuant`, `VolScalper`, `SentimentScout`) to analyze market data from different perspectives.
*   **Real-Time Dashboard ("Ari's Throne Room"):** A glassmorphism-style UI that provides a live feed of OANDA price ticks, current positions, profit & loss, and pending trade signals.
*   **Manual Trade Approval:** The dashboard includes functionality for a human operator to manually approve or reject trade signals generated by the agents before they are sent to the exchange.
*   **Resilient Streaming:** The system is designed to keep the core application and dashboard operational even if the connection to the OANDA pricing stream is interrupted.
*   **Backtesting Engine:** Includes a vectorized backtester to evaluate the performance of trading strategies against historical data.

## Setup Guide

Follow these steps to set up and run the application.

### 1. Prerequisites

*   Python 3.10+
*   An OANDA practice account with API credentials (API Token and Account ID).

### 2. Clone the Repository

```bash
git clone <repository-url>
cd <repository-directory>
```

### 3. Configure Your Credentials

The application uses a `.env` file to manage your OANDA API credentials.

1.  **Copy the example file:**
    ```bash
    cp .env.example .env
    ```
2.  **Edit the `.env` file** with your OANDA practice account credentials:
    ```
    OANDA_API_TOKEN="YOUR_OANDA_API_TOKEN"
    OANDA_ACCOUNT_ID="YOUR_OANDA_ACCOUNT_ID"
    OANDA_ENVIRONMENT="practice"
    ```

### 4. Set Up the Python Environment and Install Dependencies

The `start_servers.bat` script (for Windows) automates this process. For manual setup on other operating systems:

1.  **Create a virtual environment:**
    ```bash
    python3 -m venv venv
    ```
2.  **Activate the virtual environment:**
    *   **Windows:** `venv\\Scripts\\activate.bat`
    *   **macOS/Linux:** `source venv/bin/activate`
3.  **Install the required packages:**
    ```bash
    pip install -r requirements.txt
    ```

## Usage

### Running the Live Trading Agent

To run the application in live trading mode, which starts both the backend agent and the web dashboard:

*   **On Windows:** Simply run the batch file.
    ```bash
    start_servers.bat
    ```
*   **On macOS/Linux:** Activate your virtual environment and run `main.py` in `live` mode.
    ```bash
    source venv/bin/activate
    python main.py live
    ```

Once running, you can access the dashboard at **http://localhost:8767**.

### Running a Backtest

To run a sample backtest using the built-in engine:

```bash
python main.py backtest
```
The results of the backtest will be printed to the console.

## How It Works: System Architecture

The system is composed of several key components that work in concert:

1.  **Orchestrator (`orchestrator.py`):** This is the central nervous system of the application. It performs several critical functions:
    *   **Initializes Core Services:** It spins up the `StreamHub` and `OrderManager`.
    *   **Starts the Web Servers:** It launches two servers:
        1.  A **WebSocket server** (`ws://localhost:8766`) for broadcasting real-time data to the dashboard.
        2.  A **threaded HTTP server** (`http://localhost:8767`) to serve the static files for the dashboard (`index.html`, `style.css`, `app.js`).
    *   **Manages the Event Loop:** It is designed to be "immortal," meaning it will keep the web servers running indefinitely, even if the OANDA data stream (`StreamHub`) fails.

2.  **StreamHub (`stream_hub.py`):** This component is responsible for connecting to the OANDA v20 pricing stream for the specified instruments. When it receives a price tick, it dispatches the event to any subscribed agents.

3.  **Agent Personas (`personas/`):** These are modular Python scripts, each designed to analyze market data from a unique perspective. The `Orchestrator` subscribes these agents to the `StreamHub`'s pricing events.

4.  **Dashboard (`dashboard/`):** The frontend UI is built with vanilla HTML, CSS, and JavaScript.
    *   It establishes a WebSocket connection to the `Orchestrator`.
    *   It listens for incoming messages (e.g., `price`, `position_update`, `pnl_update`, `pending_trade`) and dynamically updates the UI components.
    *   It can send messages back to the server, such as when the user clicks the "Approve Trade" button.

5.  **Configuration (`config.py` & `.env`):** The application loads sensitive information like API keys from a `.env` file, keeping them out of version control. The `config.py` file is responsible for loading these environment variables.
